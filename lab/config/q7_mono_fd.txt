# q7_mono_fd.txt — IS THE FAST ARM BUYING ITS SPEED WITH FALSE FIRES?
# ~15 min, 2 cells, 26 throws each. Run after q_rest.
#
# WHAT q2 LEFT OPEN
#   The covariance A/B is settled on hit-course throws and the pre-registered
#   prediction is refuted: iso 7/10 and 7/10 against matched 6/10, with the two
#   controls identical (no drift), and the tca p10-p90 band going the WRONG way
#   — 0.400 / 0.470 s iso against 0.970 s matched. Matched R commits at 17.3
#   updates instead of ~5 and spends 0.312 s of dead time instead of ~0.130.
#
#   But the iso arm is OVERCONFIDENT by construction: evasion.yaml declares
#   meas_std_m 0.15 while the mono depth axis is 0.85 m. A filter that trusts a
#   bad measurement commits sooner on hit-course throws — and may also commit
#   on throws that were never going to hit. A hit-course cell CANNOT see that.
#   Until it is measured, "iso is better" is only "iso is better at the half of
#   the problem we looked at".
#
# THE PREDICTION, WRITTEN DOWN BEFORE FLYING
#   Both arms fire on FEW or NO F15/F30 throws. The mono and stereo oracles
#   differ ONLY on the depth axis (0.85 vs 0.30 m); the cross-range terms are
#   0.02 in both. A head-on throw offset by 1.5 m is discriminated almost
#   entirely CROSS-RANGE, which neither arm degrades. Depth noise corrupts tca,
#   not miss. So the stereo cell's 0/15 should roughly reproduce here.
#
#   If that holds, the iso arm's speed is not bought with false fires and the
#   q2 conclusion stands as written.
#   If iso fires on F15/F30 and matched does not, then matched R buys
#   discrimination at the price of dead time, the two arms are a real
#   trade rather than a win, and neither rescues mono — the recommendation
#   still goes to the stereo pair, but for a different reason.
#   If BOTH arms fire, the 26 m false-dodge result does not transfer across
#   sensor models and every mono number in this project needs re-reading.
#
# SCORING IS INVERTED, as in fd20_r26.0.yaml: `saved` is meaningless because
# nothing is on a hit course by construction. The measurement is the FIRE COUNT
# on F15 and F30 from the `dodged` column, with F05 as the positive control
# that proves the trigger was alive. Cross-check counterfactual_min_m >> 0.30
# on every F15/F30 row — a row that comes back on-course means the geometry
# was wrong, not that the dodge was right.
#
# Both arms use the SAME generated params as q2, so the only difference from
# those cells is the battery config:
#   mk_evasion_params.sh ~/hz_lab/params/evasion_iso.yaml  0 0 0
#   mk_evasion_params.sh ~/hz_lab/params/evasion_mono.yaml 0.85 0.02 0.02

TAG=fdmonoISO RANGE=26.0 ORACLE_RATE=0.0 DODGE_SPEED=3.0 RESP_OUT=1 CONFIG=$LAB/config/fd20_r26.0.yaml BATTERY_ARGS="-p hover_mode:=true" EXTRA_LAUNCH="oracle_params:=$LAB/params/oracle_mono.yaml evasion_params:=$LAB/params/evasion_iso.yaml" EXPECT_BANNER="0.85, 0.02, 0.02" EXPECT_MEAS_STD="0.0, 0.0, 0.0"
