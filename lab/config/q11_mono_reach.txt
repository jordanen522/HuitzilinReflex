# q11_mono_reach.txt — ONE CAMERA OR TWO? THE LAST BOM QUESTION.
# ~8 min, 1 cell. Run last, after q10.
#
# WHY THIS IS THE LAST ONE WORTH FLYING
#   Everything else remaining is either measured or needs hardware. This does
#   not: it decides how many cameras the aircraft carries, which is the single
#   largest open item in the BOM.
#
#     mono at 26 m    7/10, and the 3 losses were LATE COMMITS
#                     (tca 0.31/0.68/0.75 s), not weak escapes
#     stereo at 26 m  10/10
#
#   Mono does not dodge worse. It DECIDES LATER, because a 0.85 m depth axis
#   makes the velocity estimate converge slowly. A time deficit has two
#   currencies, and only one of them costs a second camera:
#
#     buy accuracy   second camera, calibrated pair    $178, 27 g, extrinsics
#                                                      to ~12 arcsec
#     buy time       longer lens on the one camera     $89, 13.5 g, no
#                                                      extrinsics at all
#
#   tca = range/speed - t_dead, so at 20 m/s every extra metre returns 0.05 s.
#   30 m returns 0.20 s over 26 m. If that is enough, the aircraft carries one
#   camera.
#
# THE DEPTH NOISE IS RESCALED, NOT COPIED
#   Mono depth error grows as z^2 (known-diameter prior, oracle_mono.yaml), so
#   0.85 m is the value AT 26 m. oracle_mono_r30.yaml uses 0.85*(30/26)^2 =
#   1.13 m. Holding 0.85 m at 30 m would model a camera that improves with
#   distance and would rig the answer.
#
# THE COST THAT DOES NOT APPEAR IN THIS CELL
#   Reach and FOV are the same optical trade. 30 m needs ~11.5 mm and narrows
#   the cone from +/-13.5 to about +/-11.7 deg, and fov13 already showed 10 deg
#   is marginal and 20 deg undefended. So "one camera" also means "an even
#   narrower defended sector". This cell is flown at fov 45 deliberately, to
#   isolate the depth axis; the FOV cost must be quoted alongside the result,
#   never netted out of it.
#
# PRE-REGISTERED — READ tca, NOT THE COUNT
#   Ten throws cannot separate 7/10 from 9/10, so the primary readout is
#   tca_s and track_age_s at commit. The pooled fit over 310 on-course hover
#   throws (logit p = -22.271 + 27.910*tca, LD50 0.798 s) gives P >= 0.95 above
#   tca 0.90 s.
#     commit tca >= 0.90 s  -> mono-plus-reach WORKS; expect >= 9/10, and the
#                              BOM drops to one camera plus an 11.5 mm lens.
#     commit tca ~ mono@26  -> the deficit is not a simple time deficit, extra
#                              reach cannot buy it back, and the stereo pair is
#                              required. That is equally a result.
#   Note the trigger horizon caps commit tca at 1.5 s here (30/20 = 1.50 s), so
#   a reading pinned near 1.5 s is the GATE, not the sensor.
#
#   VERIFY FIRST: first_det_range_m must come back at ~30 m. offset_forward_m
#   is 40.0 for exactly this reason.
