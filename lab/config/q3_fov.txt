# q3_fov.txt — FIELD OF VIEW: what angular sector does the BOM camera defend?
# ~70 min, 2 cells, 24 throws each. Run after q2_covariance.
#
# Every 20 m/s save so far was head-on through a +/-45 deg oracle. Both are
# harness defaults. The 10 mm M12 that buys 26 m of reach narrows the frustum
# to ~+/-13.5 deg horizontally (4.80 mm sensor width / 10 mm focal length), so
# reach and coverage are the same purchase and the campaign has only ever
# measured one side of it.
#
# The two cells are IDENTICAL except for the oracle's fov_half_angle_deg, and
# each flies the same three approach angles (0, 10, 20 deg) from
# lab/config/ang_r26.0.yaml. That makes the control internal: fov45 shows what
# oblique geometry alone costs, fov13 adds the optics on top, and the
# difference is attributable.
#
# EXPECT_BANNER asserts the FOV as well as the noise triple, because these two
# cells differ ONLY in that field — a lost oracle_params here would silently
# fly the same configuration twice and read as "FOV costs nothing", which is
# the exact wrong conclusion and a very believable one.
#
# Order: fov45 FIRST. If the control cannot save an oblique throw, the fov13
# cell has nothing left to attribute and the interesting question has changed.

TAG=fov45 RANGE=26.0 ORACLE_RATE=0.0 DODGE_SPEED=3.0 RESP_OUT=1 CONFIG=$LAB/config/ang_r26.0.yaml BATTERY_ARGS="-p hover_mode:=true" EXTRA_LAUNCH="oracle_params:=$LAB/params/oracle_stereo.yaml" EXPECT_BANNER="fov \+/-45.0 deg.*0.3, 0.02, 0.02"

TAG=fov13 RANGE=26.0 ORACLE_RATE=0.0 DODGE_SPEED=3.0 RESP_OUT=1 CONFIG=$LAB/config/ang_r26.0.yaml BATTERY_ARGS="-p hover_mode:=true" EXTRA_LAUNCH="oracle_params:=$LAB/params/oracle_stereo_fov13.yaml" EXPECT_BANNER="fov \+/-13.5 deg.*0.3, 0.02, 0.02"
